# Paper entry outage: October 19–November 2, 2026

The OpenAI project used by the GitHub live workflow exhausted its credits on
October 19. This is a dependency outage, not an absence of strategy signals.

Evidence: the [October 19 run](https://github.com/dmboynton56/llm-advisor/actions/runs/39260254083)
logged successful AAPL and MSFT order submissions at 14:47 and 16:27 UTC.
At 17:02 UTC, market analysis reported HTTP 429 with type `insufficient_quota`
and code `credit_balance_exhausted`. Subsequent trade validation calls failed
with the same error. Submission logs establish order attempts accepted by the
broker, not independently verified fills.

These counts use `TRADE SIGNAL DETECTED`, `LLM VALIDATION APPROVED`, and
`TRADE EXECUTED SUCCESSFULLY` log markers. Credit-exhaustion errors appear in
every session. All workflows nevertheless concluded successfully because the
validator converted exceptions to rejected decisions and completion checks only
checked the normal session end reason.

The repair distinguishes validation errors from genuine rejections and monitors
the live LLM client, including market and shadow reviews. Provider errors cause
a failed segment only after normal position management and shutdown telemetry.
Artifact names, session end reasons, calendar checks, EOD ingestion, prompts,
models, trading thresholds, and reconciliation calculations are unchanged.

Operator action remains necessary: restore funding to the project behind the
workflow's OpenAI credential. Code cannot replenish credits. After funding is
restored, verify successful calls in a normal scheduled segment; do not disable
validation or force an order to demonstrate recovery.

SPY also reports a placeholder daily-bias model; several experimental stocks
report absent trained models. These are separate, visible data-quality issues.
This repair does not bypass the ETF model-quality gate or claim every signal
would otherwise have traded.
